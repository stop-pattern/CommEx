# 長期タスクの開発・再開ガイド

このガイドは [AGENTS.md](../AGENTS.md) の運用手順を具体化します。製品仕様の承認や
機能の完了判定を置き換えるものではありません。新しい担当者やエージェントが会話履歴なしで
次の一手を再現できる状態を保ちます。

ユーザーはVisual Studio 2026でルートの `CommEx.slnx` を開いて開発します。
agentはVS Codeで `CommEx.code-workspace` を開き、統合Windows PowerShellターミナルを
リポジトリルートに置いて、既存の `scripts/` からビルド・検証・Git操作を行います。
同じファイルと出力先を共有するため、編集の競合や同時ビルドを避けます。
具体的な開き方と初期設定は [開発環境ガイド](build-configuration.md) を参照してください。

## goal と着手条件

作業を始める前に `reports/<work-id>/goal.md` を作成・更新し、目的、承認された範囲、
成果物、受入条件、制約、依存関係を明記します。feature の作業では対応する spec/plan/tasks を
参照します。文書整備などは feature とは別の説明的な work-id を使用します。

依頼内容から明らかな実装上の選択は自立して進めます。外部プロトコル、安全動作、互換性、
保存形式、利用者に見える動作を変える未承認の判断は推測で確定せず、該当作業を BLOCKED として
必要な判断を記録します。依存しない承認済み作業は継続できます。新たな承認のない作業へ
goal を拡張したり、完了条件を都合よく変更したりしません。

セッション用の goal 管理機能がある場合も、ファイル上の goal と状態を同期します。
チャット、ツール内部状態、subagent の記憶だけを唯一の記録にしません。

## 開発サイクル

1. **再開・計画**: goal、現在の進捗、仕様、タスク、過去の失敗と証跡を読む。実際の Git 状態、
   既存プロセス・接続・配置状況と照合し、最小の検証可能な増分を選ぶ。
2. **実装**: 該当するテストを先に、または実装と並行して用意する。仕様に沿う最小の変更を行い、
   関連文書の本文・表・例・タスクも整合させる。
3. **ビルド・局所検証**: リポジトリの build/test スクリプトで確認し、コマンド、終了コード、
   対象リビジョン、時刻、ログ参照を記録する。コードの変更前後を混同しない。
4. **エラー解析・修正**: 失敗証跡を保存し、再現条件と反証可能な原因仮説を立てる。
   仮説を区別できる最小の実験を行い、結果と棄却理由を記録する。修正後は再ビルド・再検証する。
5. **配置・書込み**: 必要な事前検証を通過した成果物だけを、宣言済みの検証先へ配置する。
   下記の対象・競合・復旧確認を行う。CommEx では通常 DLL 等の配置を指し、機器への
   ファームウェア書込みを新たに許可するものではない。
6. **実環境デバッグ**: 対象プロセスでシナリオを実行し、バージョン、ログ、通信データ、
   UI/状態変化、応答性、終了を観測する。コピー成功やプロセス起動だけを合格にしない。
7. **反復・統合検証**: 必要に応じて解析→修正→ビルド→配置→観測を繰り返す。
   scripts/verify.ps1 と各受入条件で、実装したリビジョンを検証する。
8. **コミット・記録**: 適用対象の検証を通過した意味のある増分をその都度コミットし、
   進捗へコミットIDと次の操作を残す。機能全体が未完でも、検証済みの独立した増分を溜め込まない。
9. **完了・中断**: 全必須基準が満たされた場合のみ機能を完了扱いにする。中断・BLOCKED の場合も、
   失敗、試行数、配置状態、最小の解消条件、再開手順を残す。

一つのプロンプトやターンはコミット単位ではありません。一回の依頼を複数の意味あるコミットへ
分け、タスクごとにコミットを分離します。同じタスクに必要な実装・テスト・整合性維持のための
文書群は同じ単位にまとめ、別タスクや既存の未コミット変更を混ぜません。

編集・ステージの前に既存のタスク記録、担当、Gitの差分を確認し、変更範囲が重なる場合は
担当者と調整します。同じファイルに複数タスクの差分がある場合は、今回のタスクに属する
レビュー済みの差分だけを選択してステージします。1タスク1コミットに固定せず、適用対象の
検証を通過した意味のある増分ごとにコミットし、そのIDを該当タスクのprogress/journalに残します。

## 配置・書込みとリソース所有

- config/repo.local.json に実パスが宣言され、対象機能に対して許可された検証先だけを使用する。
  別のBVE環境、ユーザーデータ、機器を推測で選ばない。
- 成果物の元コミット、ビルド条件、ハッシュ、対象ホスト/モードを確認する。古い成果物の配置を防ぐ。
- 対象プロセス、COMポート、待受ポート、ブローカー、配置先の所有者を進捗へ記録する。
  書込み・停止・接続試験は同一リソースについて一人の担当に直列化する。
- 対象が利用中なら安全な停止・アンロードを先に行う。無関係なプロセスを停止しない。
  既存成果物のバックアップと復旧手順を確保し、実際に変更した配置状態を記録する。
- 配置後は読み込まれた成果物と動作を確認する。失敗時は契約どおり停止または復旧し、失敗も保存する。
  不明な配置状態を成功とみなさず、再開時に必ず照合する。
- 検証で開始したワーカー、プロセス、ポート、UIは終了時に解放する。引継ぎが必要なら所有者、
  状態、停止方法を明示する。鍵や認証付きコマンドラインは記録しない。

## コンテクストをファイルへ残す

`reports/<work-id>/` に次の記録を置きます。形式とテンプレートは [reports/README.md](../reports/README.md)
を参照してください。

| ファイル | 内容 | 更新方法 |
|---|---|---|
| goal.md | 目的、承認範囲、成功条件、依存・制約 | 方針変更時に本文を整合させて更新 |
| progress.md | 現在状態、担当、最新コミット、作業差分、試行数、配置状態、次の具体操作、BLOCKED理由 | 常に現在の再開用スナップショットにする |
| journal.md | 行動、調査結果、仮説、実験、結果、根拠、判断 | 意味のある出来事ごとに時系列で追記 |
| summary.md | 達成内容、検証、制限、残課題 | 完了・中断時に整理 |
| result.json | 既存スキーマに従うfeatureの最終検証結果 | 検証結果として作成。途中状態を捏造して埋めない |
| logs/、screenshots/、test-results/ | 生ログ・画面・実行証跡 | Git管理外に保持し、公開可能な参照・要約だけを記録 |

計画変更、重要な発見、各ビルド/試験/配置の前後、失敗と仮説の更新、subagentへの割当と統合、
コミット、ブロック、引継ぎ、ターン終了・コンテクスト圧縮前に記録します。
長い処理は開始前に目的・コマンド・証跡先・pending状態を保存し、終了後に結果を確定します。
pendingのまま再開した処理は実際の状態を確認するまで成功とも失敗とも断定しません。

細かな進捗でも、次の判断や再現に必要な情報は残します。思考の逐語録や重複した全文コピーではなく、
観測事実、判断理由、根拠、次の操作を記録します。必要な記録をセッション終了まで溜めません。
書込み中断に備えて進捗ファイルを完全な内容で置換し、矛盾した部分更新を残さないようにします。

## 再開手順と試行上限

新セッションでは AGENTS.md → goal.md → progress.md → 関連する journal.md/証跡 →
spec/plan/tasks の順に確認します。Gitのbranch/HEAD/差分と照合し、他担当の変更を上書きしません。
保存した次の操作と実状が違えば、理由と修正した計画を記録してから続けます。

maximumFeatureAttempts は config/repo.local.json の値を使い、消費済み回数を進捗に保持します。
セッション、subagent、再起動、コンテクスト圧縮で回数をリセットしません。
1回の機能試行は、記録した計画/仮説に基づく修正とその検証の一巡です。
局所実験も journal に残し、試行の数え方を変えて上限を回避しません。
上限到達時は根拠と最小の解消条件を残して BLOCKED。再開条件や追加の試行予算は明示的に記録します。

ツールのエラー、環境不足、外部待ちを、無限ポーリング・同じ仮説の繰返しで隠しません。
セッションが終了した後も処理が継続すると約束せず、ファイルから再開できる状態を保証します。

## subagent による並行作業

解析、調査、参照照合、レビュー等の独立したread-only作業は適宜委譲します。
実装、テスト、文書編集も独立した責任範囲に分割し、積極的に並行化します。

委譲時は goal、対象、必要な背景、読むべき資料、変更可能ファイル、変更禁止範囲、
期待する成果物/証跡、検証方法を渡します。共有チャットの暗黙知に依存しません。
progress.md の担当表に所有範囲と進行状況を保存します。

同じファイル、Git index、コミット、デプロイ先、BVEプロセス、COMポート等は共有資源です。
編集範囲が重なる場合は直列化または承認された分離環境を使用します。同じ作業ツリーでは
coordinator がステージ・コミット・統合を担当し、各agentが同時にGitを変更しないようにします。

subagentの報告は未検証の入力として扱い、coordinatorが差分、根拠、仕様適合性を確認し、
必要な統合テストを行ってから完了扱いにします。担当の終了や中断で未記録の変更を残しません。
分割が適さない小さな変更や密結合なデバッグは、一人で処理する判断も記録できます。

## 文書を全体として整合させる

仕様を変更したら、計画、タスク、受入基準、API/設定例、README、agent指示、運用ガイドの
影響箇所を検索します。追加/削除内容が初めから存在したかのように、該当節の本文・表・例を
再構成します。「追記が旧本文を上書きする」方式で矛盾を残しません。
削除時には参照、タスク、例、索引も更新します。必要な根拠は決定記録に移します。

現行仕様と履歴は区別します。journal、過去のテスト結果、コミットに紐づく報告は当時の事実であり、
現在に合わせて書き換えません。訂正が必要なら対象・理由を明示した新しい記録を加えます。
製品資料の重複は参照で減らし、READMEとAGENTSのフォルダ表のように複製が必要なものは同時更新します。

## プライバシーとコミット

コミット前に staged diff、追加ファイル名、コミットメッセージ、author/committer設定の適切性を
確認します。名前、メール、ユーザー名を含むフルパス、ホスト名等の識別情報、トークン、秘密鍵、
認証情報、接続文字列、機密のログ/画面/データを含めません。Gitの表示名/メールにも、
利用者が公開を認めた識別情報または匿名設定だけを使います。グローバル設定を勝手に変更しません。
公開可否が不明な場合は、実在人物を名乗らない作業用の匿名IDをコミット単位で使用します。

コマンドの引数、スタックトレース、ログのヘッダー、スクリーンショット、生成レポートも確認します。
実パスはリポジトリ相対パス、環境変数、プレースホルダーへ置換し、生証跡は除外済みの保存先に置きます。
Gitignore は検出・消毒機能ではなく、既に追跡済みのファイルを守りません。
秘密が見つかった場合は内容をチャットや報告へ再掲せず、対象の種類と対処だけを記録します。
過去に漏えいした可能性があれば利用者へ知らせ、無断で履歴を書き換えません。

## 現在のスクリプトの到達点

| スクリプト | 現状と使用条件 |
|---|---|
| build.ps1 / test-unit.ps1 / test-integration.ps1 | 正式なビルド・検証入口。必要なsolution/runnerが整った後に使う |
| verify.ps1 | 検証段階の順次実行。長期タスク管理や途中状態の復旧は行わない |
| test-bve.ps1 | 意図的に失敗する未実装プレースホルダー |
| deploy-bve.ps1 | 設定されたDLLを1ファイルコピーする補助。停止/バックアップ/ハッシュ照合/復旧/6環境切替は未実装 |
| autonomous-loop.ps1 | 長期無人運用には未対応。固定tasks参照、一括ステージ、完了時一括コミット、試行数の非永続化等を解消するまで起動しない |

これらの機能が文書を追加しただけで実装されたとは扱いません。
不足する自動化は [基盤タスク](../specs/000-product/tasks.md) で追跡します。

# 06. シリアル（COM）仕様

## 対応プロトコル

次の 4 種から選択可能とする（将来拡張可）。

1. bids互換（ヘッダ `EX/TR`）
2. communication.dll互換
3. BveSerialOutput互換
4. バイナリ独自形式

---

## 6.1 共通要件

- 複数 COM ポート同時利用に対応
- ポート単位で設定を独立管理
- 各ポートでプロトコル種別を個別選択できる

---

## 6.2 bids互換（BIDSid_SerCon 準拠）

準拠元:

- https://github.com/Tralsys/BIDSid_SerCon
- `CommandList.pdf` / `CommandList.xlsx`

### 受け入れフレーム（上位仕様）

- 要求: `TR` + `<識別子1文字>` + `<要求情報可変長>` + `CRLF|LF`
- 応答: `TR` + `<識別子1文字>` + `<要求情報可変長>` + `<区切り記号>` + `<返答値>` + `CRLF|LF`
- エラー: `TR` + `E` + `<エラーコード>` + `CRLF|LF`

### 受理対象識別子

- `R`: レバーサー
- `S`: ワンハンドル
- `P`: 力行
- `B`: 制動
- `K`: キー操作
- `I`: 運転情報
- `V`: バージョン
- `E`: エラー

### 受理例

```text
TRR0
TRKDn
TRIE1
TRV100
```

## 6.4 BveSerialOutput互換（SerialOutputEx 準拠）

準拠元:

- https://github.com/GraphTechKEN/SerialOutputEx

### 実装読み取りから抽出した上位仕様

- 電文は ASCII ベースの文字列送信を前提とする。
- 固定ヘッダを要求しない（項目連結型）。
- 設定（`SerialOutputEx.xml` 相当）で定義した項目順に値を連結して 1 フレーム化する。
- 終端は `\r`（実装上）を基本とし、互換のため `\r\n` / `\n` も受理可能とする。

### 受け入れフレーム（上位仕様）

`<field1><field2>...<fieldN><EOL>`

- `field` は数値/符号付き数値/記号（例: `P`,`N`,`H`,`F`,`B`）/固定文字列を許容
- フィールドの桁数・基数・スケールは設定ファイル準拠

### 代表的なデータ種別（準拠実装で確認できる範囲）

- 列車位置 / 速度 / 時刻
- 圧力系（BC, MR, ER, BP, SAP）
- 電流
- ブレーキノッチ / 力行ノッチ / レバーサー
- ドア状態
- パネル値 / サウンド値
- 固定文字列

---

## 6.5 バイナリ独自形式

- ASCII 文字列は不要。
- バイナリ（byte列）として送受信する。
- フレーム定義（先頭識別子、長さ、CRC等）は別途策定する。
